# youngsemdems site (demo)

The demo website for the Young Democrats of Seminole County, Florida (YDSC, handle `youngsemdems`).
Kira is building it in this folder. The organization's name, ages and links live in
`assets/js/config.js` (`org`, `site`, `links`); this README does not repeat them, so it cannot go out
of date. It is a demo for now, for party sign-off, and it is built to move to a real domain with
config changes only.

- Plain static site: HTML, CSS and vanilla JavaScript. There is **no build step**. The folder is the
  site, and it works from `file://`, from `python3 -m http.server`, and on Cloudflare Pages or
  Netlify.
- Classic `<script>` tags only (no ES module imports), and no `fetch()` of local files. Data ships
  as `data/*.js` files that set `window.YSD_DATA`.
- Demo mode (`YSD_CONFIG.demo === true`) keeps all state in the browser. Joins, counters and
  uploads go nowhere until the integrations are configured.
- The only server code is two optional serverless functions (Cloudflare Pages Functions in
  `functions/`, with Netlify twins in `netlify/functions/`). Secrets live only in the host's
  environment variables.
- There is **no chat assistant, LLM call or "ask" endpoint** anywhere. Kira cut it. The tests
  fail if one appears.

## Run it locally

```sh
cd youngsemdem
python3 -m http.server 8000        # then open http://localhost:8000/
# or simply open index.html in a browser (file://)
```

Features that need http (the service worker and some clipboard and share APIs) stay off on
`file://`, and the pages still work there. To run the serverless functions locally you need a host
CLI: `npx wrangler pages dev .` (Cloudflare) or `npx netlify-cli dev` (Netlify). See DEPLOY.md.

## Scripts

Nothing to install: the tools need Python 3.11+, Node 18+ (22 tested), and Playwright for the
browser checks (preinstalled globally here; otherwise run `npm i -g playwright` and then
`npx playwright install chromium`). `npm run <name>` is a shortcut for each command.

| npm script | Command | What it does |
|---|---|---|
| `serve` | `python3 -m http.server 8000` | Local server |
| `sync` | `python3 tools/sync_partials.py` | Copy `partials/*.html` into every page between `<!-- @name -->` markers, setting `aria-current="page"` and the `{{root}}`, `{{site}}` and `{{path}}` tokens |
| `sync:check` | `... --check` | Exit 1 if any page is out of date |
| `check` | `node tools/check_site.js` | Playwright crawl of every root-level page at 390x844 and 1440x900: console and page errors, failed requests, overflow, alt text, meta and social tags, links and anchors, duplicate ids, headings, accessible names, tap targets, lang, plus axe-core. Writes `tools/check_report.json` |
| `check:strict` | `... --strict` | Launch gate: warnings count as errors, and noindex pages fail |
| `csp` / `csp:check` | `node tools/csp.js --write` / `--check` | Regenerate (or verify) the Content-Security-Policy in `_headers` from the endpoints and analytics settings in `config.js` |
| `manifest` / `manifest:check` | `node tools/manifest.js --write` / `--check` | Copy name, description and colours from `config.js` into `manifest.webmanifest` |
| `sitemap` | `python3 tools/make_sitemap.py` | Write `sitemap.xml` (needs `site.url` in config or `--base https://...`; `--robots` adds the Sitemap line) |
| `credits` / `credits:check` | `python3 tools/credits.py` | Write (or verify) `CREDITS.md` |
| `preflight` | sync check + csp check + manifest check + site check | Run before every deploy |
| `test` | core, video and tooling tests | `node tests/infra/<name>.test.js` each; exit 1 on failure |

## Working rules

- Load order on every page: `assets/js/config.js`, then `assets/js/store.js`, then the rest. Each
  module tolerates missing optional modules. `tools/check_site.js` warns when the order is wrong.
- Keep inline `<script>` out of pages. The production CSP (`script-src 'self'`) blocks them, and the
  site check reports the violation. Put the code in a file under `assets/js/`.
- Use `{{root}}` for links inside partials, never `/about.html`. Root-relative links break on `file://`.
- Every number and person in demo data is flagged `demo: true` and hidden when `demo` is `false`.
- Facts on the site need a source (see `docs/research/`). Don't invent stats or quotes.
